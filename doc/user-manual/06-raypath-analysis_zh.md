# 光路分析

「Raypath Analysis」窗口回答的问题是：「天空某个区域的光，是由哪些光路做出来的，各占多少」。
与主预览不同，它不产出画面——点击 Analyze 会发起一轮**专用、不渲染**的运行，按完整光路给每条
光线分组，并报告每一组占总能量的比例。

> **不需要先跑模拟。** Analyze 提交的是面板上当前的文档——与按 Run 会渲染的场景完全相同——所以
> 刚打开的 `.lmc`、从未跑过的文档、上次运行后又改过的文档都可以直接分析。屏幕上的画面不是这份
> 文档的时候，按钮下方会有一行提示（「No rendered image for this document yet…」/「Image is from
> a previous configuration…」）；列表描述的始终是当前配置的场景。唯一会让按钮禁用的是正在进行的运行。

## 1. 面板在哪

点击顶栏里 **Colors** 按钮旁边的 **Analysis** 按钮（路径图标）。它会打开一个独立的非模态
「Raypath Analysis」窗口，可以和主预览同时开着——不会替换或嵌入任何现有面板。

## 2. 选取分析区域（ROI）

**Region** 一行提供三档：

| 档位 | 分析范围 |
|------|---------|
| **Whole sky（全天）** | 场景里射出的所有光线，不做任何空间筛选。 |
| **In frame（可见区域）** | 只统计落在当前画幅内的光线（与预览用的同一套镜头/视角/可见范围/正面判定）。选这一档需要屏幕上有预览；已选中而预览不在时，画幅取文档自身的视角与模拟分辨率。 |
| **Point（点）** | 以一个方向为中心的锥形邻域，在预览上显示为一个可拖动的标记点。 |

**Point 标记点**：切到 Point 模式时，标记点默认放在当前视角的正中央（前提是屏幕上有预览，且
之前没有留下一次点选的位置）。它每一帧都随视角重新投影，而不是钉在某个屏幕位置上——转动或
平移视角时它不会被落下。把鼠标悬停在它上面会变成手形光标，直接拖动即可把中心移到新位置；
**Pick on preview** 旁边显示的高度角/方位角读数会随拖动实时更新。也可以改按 **Pick on preview**：
窗口顶部会出现一条提示条（"Click on the preview to set the centre — Esc to cancel"）并把光标
换成十字线，在预览上任意位置点一下即可把标记点移过去，或按 Esc 取消。

只要有了中心，**Radius** 滑杆就可以拖动——甚至在按 Analyze 之前也可以。在还没有结果时，拖动它
只改变预览上那个 ROI 圆环的大小；有了结果之后，它改变的是报表把能量加到锥心多远处，同样
**不会重跑分析**：底层这一轮统计本来就会把整个锥按细密的角度环记录下来，滑杆只是在显示时决定
加到第几环为止。也就是说，点一次 Analyze 之后可以反复来回拖滑杆，即时看到不同半径下的结果。

## 3. 发起分析

Analyze 按钮上方的 **Infinite rays** 与 **Rays(M)** 决定分析要跑多少光线——这是它自己的预算，
与文档的 **Rays** 设置相互独立（第一次打开窗口时会取该值作为初始值）。关掉 **Infinite rays**
并拖动 **Rays(M)**，可以让分析按一个固定的总数（单位百万，覆盖所有波长）跑；打开它则会一直跑到
你按 Stop 为止。任何区域档位下都没有单独的提前停止设置——光线预算与 Stop 按钮是运行结束的
唯二方式。

点击 **Analyze**。一轮专用运行会遍历场景并按光路分组光线；运行中可以点 **Stop** 提前结束，
用已经攒到的数据出结果——按 Stop 不会丢弃已有结果，只是停止继续累积。跑完（或被提前停止）后，
下方的结果列表会填入内容。

**分析永远走 CPU**，即使你为渲染选的是 Metal 或 CUDA 后端也一样。这是刻意的设计，不是可以关掉的
降级：GPU 追踪路径不保留这个功能需要的逐光线记录。窗口里**没有**为此单独显示提示——Analyze 可能
比同一场景的 GPU 加速渲染慢一些，仅此而已。

如果配置在上一次运行之后又改过，Analyze 照样可用，报告的是改后的文档——屏幕上的画面还是旧的，
按钮下方那行提示会一直说明这一点，直到你重新按 Run。

## 4. 读懂结果列表

每一行是一条不同的光路——光线从起点到出射经过的完整晶体与面序列。穿过一个晶体的光路直接写
面序列：`3-5`（从 3 号面进、5 号面出）。若某个散射层里有多种晶体，则在前面标出晶体：`C1(3-5)`。
多次散射时每一层各自带括号、层与层之间用 ` -> ` 连接，从根层开始：`(3-5) -> (1-3)`，层内有多种
晶体时写作 `C1(1-3) -> C4(3-5)`。各列含义：

| 列 | 含义 |
|----|------|
| **Raypath** | 该链的可打印名称，格式如上。 |
| **Energy** | 这条光路在当前区域总能量中的占比（百分比）。列表按此列降序排列。 |
| **Cumulative %** | 从第一行累加到当前行的 Energy 之和，方便一眼看出前几行合计占了多少光。 |
| **Rays** | 计入这条光路的光线数。 |
| **+/-** | 该计数的统计噪声（1/√N），避免尾部条目的小数字被误读成精确值。如果这一行接管了某个能量小得多的条目腾出的位置（见下方「记录上限」），括号里还会显示它有多少能量可能其实属于那个条目。 |

一条光路的能量占比**不等于**它在画面上看起来有多显眼：随机朝向晶体产生的弥散、覆盖面很广的
弱光路，总能量可能高于一条集中、明亮的窄弧，因而在列表里排得更靠前。这个列表回答的是
「有多少光」，不是「多显眼」。

**记录上限。** 分析保留的是一个足够大但固定的不同光路数量——普通场景根本不会碰到这个上限——
而不是随光线数或散射层数无限增长。如果某个场景产生的不同光路确实超过了这个上限，列表底部会
出现一行灰色的 **other**：它是没能放进具名行的那部分能量与光线数，也正是它让 Cumulative % 列
在最后一行恰好到达 100。这一行永远不可选中，也不能被排除，因为它并不对应某一条具体的光路。
按钮下方的状态行会在发生这种情况时提示（"record full (N hits)"）；对本工具自带的参考场景以及
大多数实际配置，这种情况根本不会发生。

**对称性（P / B / D）**。列表上方的三个复选框决定哪些光路算作同一行——与 filter 编辑器用的是
同一套 P、B、D 对称（棱面旋转、底面反射、镜像）。三个全开（默认）时，`3-5` 的六个旋转和它的
镜像合成一行；关掉 D，镜像路径 `3-7` 会单独成行；关掉 P，每个旋转都各成一行。这是**显示态**
的选择：分析记录的是未约化的每一条路径，切换复选框会立刻用手头的结果重新分组——不重跑、总量
不变，选中的行只要它的光路仍然是一行就保持选中（被并进别的行的光路则自然取消选中）。如果分析
之后又按过 Run，手头的结果就不能再重新分组了；窗口会提示列表当前按哪种对称显示，下一次
Analyze 会应用复选框的设置。

## 5. 「Exclude this raypath」（排除此光路）

选中一行，点击 **Exclude this raypath** 会生成一个过滤器，把走这条精确路径的光线剔除掉——采用
列表当前显示所用的 P / B / D 对称，因此过滤器剔除的恰好是这一行合并进来的那些路径，不多不少——
并把文档标为已修改——再按一次 Run 就能看到去掉它之后的画面。这复用的是在晶体编辑器里手动编辑
filter 的同一套机制，不是新发明的规则。

以下情况按钮会被禁用，并附带说明为什么：

- 没有选中任何行；
- **这条光路跨越了不止一个晶体**（对应多次散射的跨层链）——filter 挂在单个晶体上，今天没有
  办法表达「排除这条精确的跨晶体序列」。只有单晶体、单层的光路可以用这种方式排除；
- 这条光路经过的晶体已经不在当前文档里了（比如分析之后你改过晶体列表——重新跑一次再分析）；
- **用到该晶体的某个条目已经挂了一个 In filter**——Exclude 只会往 Out filter 上追加，所以这里
  按钮保持禁用；手动编辑那个 In filter，或把它的 action 改成 Out，才能继续。

如果该晶体已有的是一个 **Out** filter，按钮不会禁用：点击后会把这条光路作为又一个被排除的
选项追加进那个 filter——tooltip 会说明是哪个 filter、还有几个条目共享它——而不是被拒绝。
重复排除同一条光路不会产生重复项。
